# lawscan

อ่านกฎหมายไทยจาก PDF ราชกิจจานุเบกษา ออกมาเป็น CSV 33 คอลัมน์ตามรูปแบบของผู้ดูแล

```
PDF → OCR → กฎ → โมเดล → รวม → CSV → เทียบ
```

ไม่มีฐานข้อมูล ไม่มีเว็บ ไม่มีคิวรีวิว ทุกอย่างเป็นไฟล์ที่เปิดอ่านได้

## คำสั่ง

### `lawscan etl` — ใช้ตัวนี้เป็นหลัก

รันทั้งงาน: อ่าน PDF ทุกไฟล์ → กฎ → โมเดล → CSV → เทียบกับไฟล์อ้างอิง

```bash
lawscan etl                          # pdfs/ → tests/
lawscan etl /path/to/pdfs            # โฟลเดอร์อื่น
lawscan etl --into runs              # เก็บผลที่อื่น
lawscan etl --no-compare             # ไม่ต้องเทียบ
lawscan etl --fresh                  # ถามโมเดลใหม่ทุกฉบับ
```

**ค่าเริ่มต้นคือใช้คำตอบเดิม** ฉบับไหนเคยรันครบทั้งห้าคำถามในรอบก่อน จะคัดลอกคำตอบ
มาใช้ ไม่ถามโมเดลซ้ำ — 40 ฉบับที่เดิมใช้ 25 นาที เหลือ 1.4 วินาที

ขาดกลางทางกด `Ctrl-C` แล้วสั่งซ้ำได้ งานที่ทำไปแล้วไม่หาย

`--fresh` มีไว้ตอนแก้พรอมป์ ถ้าไม่ใส่ คุณจะกำลังวัดพรอมป์ใหม่ด้วยคำตอบของพรอมป์เก่า

### คำสั่งย่อย — สำหรับตอนที่ช่องใดช่องหนึ่งผิด

```bash
lawscan read  pdfs/100002.pdf              # ข้อความที่ OCR อ่านได้
lawscan read  pdfs/100002.pdf --full       # ทั้งหมด ไม่ตัด

lawscan rules pdfs/100002.pdf              # กฎอ่านอะไรได้ ไม่เรียกโมเดล ไม่เสียเงิน

lawscan ask identity pdfs/100002.pdf                 # ถามโมเดลข้อเดียว
lawscan ask business pdfs/100002.pdf --show-prompt    # ดู prompt ที่ส่งจริงด้วย

lawscan scan pdfs/ --out out/r.csv --workdir out/     # pipeline ดิบ ควบคุมเอง
lawscan scan pdfs/ --no-llm --out out/r.csv           # กฎอย่างเดียว ฟรี
lawscan scan pdfs/ --reuse  --out out/r.csv           # ประกอบใหม่จากคำตอบเดิม

LAWSCAN_MODEL=gpt-5-nano lawscan scan pdfs/  # เปลี่ยนโมเดล/ค่าย (gpt · deepseek · kimi · gemini)
LAWSCAN_EFFORT=minimal ...                 # เฉพาะ gpt-5/o-series: คุมโทเคนคิด

lawscan diff out/r.csv                     # เทียบ
lawscan diff out/r.csv --examples          # พร้อมตัวอย่างที่ไม่ตรง
lawscan diff out/r.csv --out cells.csv     # เขียนไฟล์เทียบทีละช่อง
lawscan diff out/r.csv --xlsx cmp.xlsx --workdir out/   # สมุดงาน: แผ่นสรุป + แผ่นรายช่อง

lawscan record out/r.csv --note "แก้อะไร"  # เก็บผลรอบนี้เป็นโฟลเดอร์
```

`--no-llm` กับ `--reuse` คือสิ่งที่ทำให้แก้กฎแล้ววัดใหม่ได้ฟรี ไม่ต้องจ่ายค่าโมเดลซ้ำ

สามขั้นกลางตอบคำถามคนละชนิด และ**ต้องดูแยกกันได้**

| ขั้น | ตอบอะไร | ตรวจยังไง |
|---|---|---|
| `ocr` | หน้ากระดาษนี้เขียนว่าอะไร | `lawscan read` |

`rules` ไม่เรียกโมเดล `llm` ไม่อ่าน PDF ทั้งสองไม่รู้จักกัน — `merge` เป็นที่เดียวที่ตัดสิน
ว่าใครชนะเมื่อทั้งคู่ตอบคำถามเดียวกัน

## หลักการ

### กฎมาก่อนโมเดล

ที่ใดเอกสารระบุสิ่งหนึ่งในรูปแบบตายตัว โค้ดอ่านเอง คำตอบของโมเดลไม่มีสิทธิ์ออกเสียง
`Row.put()` ปฏิเสธไม่ให้คำตอบโมเดลทับคำตอบของกฎ ลำดับใน `pipeline.py` คือกลไก
ไม่ใช่เงื่อนไข `if` ที่กระจายอยู่ทั่วโค้ด

ตัวอย่างที่ชัดที่สุด — **ประเภทกฎหมาย** โมเดลตอบ `REGULATION` ส่วนไฟล์ผู้ดูแลเขียน
`ระเบียบ` ผิด 40 จาก 40 ฉบับ ทั้งที่โมเดลอ่านเอกสารถูก มันผิดเรื่องคำศัพท์ ไม่ใช่เนื้อหา
ย้ายมาให้กฎอ่านคำแรกของเอกสาร **40/40 ทันที**

### หนึ่งคำถาม หนึ่งไฟล์

`prompts/` มีห้าไฟล์ ไฟล์ละคำถาม ไม่ใช่คำสั่งเดียวยาว 60,000 ตัวอักษรที่ถามทุกอย่าง
รวดเดียว — รูปแบบสองระดับของช่องกลุ่มเป้าหมายที่ระบบเดิมพยายามสามรอบไม่เคยได้
ที่นี่ได้ตั้งแต่รอบแรก เพราะพรอมป์ 31 บรรทัดที่พูดเรื่องเดียว

| ไฟล์ | ถามอะไร | เติมช่องไหน |
|---|---|---|
| `identity.md` | นี่คือกฎหมายอะไร ใครออก | ชื่อกฎหมาย · หน่วยงานกำกับ |
| `parent.md` | ออกโดยอาศัยอำนาจตามกฎหมายใด | กฎหมายแม่ |
| `audience.md` | ผูกพันใคร | กลุ่มเป้าหมาย |
| `business.md` | ธุรกิจใดต้องรู้ | Core / Support + เหตุผล |
| `summary.md` | สาระสำคัญ ต้องทำอะไร | สรุป · คำแนะนำ · ใบอนุญาต · แท็ก |

พรอมป์ถูกอ่านใหม่ทุกครั้งที่เรียก แก้ไฟล์แล้วมีผลทันที ไม่ต้อง restart — **แต่ห้ามแก้
ระหว่างรัน** ไม่งั้นเอกสารครึ่งแรกกับครึ่งหลังจะใช้คนละพรอมป์และวัดผลไม่ได้

### วัดก่อนเขียน แก้แล้ววัดซ้ำ ถ้าแย่ลงให้ย้อน

ทุกกฎในโปรเจกต์นี้ผ่านการทดสอบกับข้อมูลจริงก่อนเขียนลงโค้ด ตัวเลขที่วัดได้เขียนไว้
ในคอมเมนต์ เพื่อให้การแก้ครั้งหน้ามีอะไรให้เถียง

## บั๊กที่เจอ และวิธีที่เจอ

เก็บไว้เพราะทุกตัวเจอด้วยการวัด ไม่ใช่ด้วยการอ่านโค้ด

### วรรณยุกต์หลุดไปท้ายบรรทัดก่อนหน้า — หัวราชกิจจาฯ อ่านไม่ได้เลยทั้ง 40 ฉบับ

```
้
หนา   ๘่
เลม   ๑๓๗   ตอนที่   ๑๓    ก
```

`เล่ม` แตกเป็น `่` + `เลม` กฎหาไม่เจอสักฉบับ วัน/เดือน/ปีที่ประกาศ ผิด 40/40

ตัวซ่อมย้ายวรรณยุกต์กลับตามหลักสะกดไทย — ข้ามสระนำหน้า (เ แ โ ใ ไ) และข้าม ห/อ
ที่นำพยัญชนะอื่น **0/40 → 40/40**

### `ำ` หายกลายเป็นช่องว่าง

`ำ` คือนิคหิตบนสระอา ฟอนต์ทิ้งนิคหิต `อำนาจ` เลยออกมาเป็น `อ านาจ`

ทั้ง 40 ฉบับ คำว่า อำนาจ กำหนด สำนัก ดำเนิน นำเข้า สำหรับ **ไม่ปรากฏเลยแม้แต่ครั้งเดียว**
วลี `อาศัยอำนาจตามความใน` ที่ใช้ระบุว่าเป็นกฎหมายลูก หาไม่เจอ กฎที่พึ่งมันจึงไม่เคยทำงาน

```
คำไทยที่ถูกต้อง   899 → 1,961
คำที่พัง            49 →    49   (ของเสียเดิม ไม่ใช่จากการซ่อม)
```

ปลอดภัยเพราะไม่มีคำไทยคำไหนขึ้นต้นด้วยสระอา

### คอมเมนต์บอกว่าทำ แต่โค้ดไม่ได้ทำ — เทสต์จับได้ 3 ตัวทันทีที่เขียน

1. ตัวย้ายวรรณยุกต์เขียนว่า "จำกัดสี่ตัวอักษร กันไม่ให้แตะคำอื่น" แต่มันจำกัดแค่ว่า*จับ*มากี่ตัว
   `พระราชบัญญัติประกอบรัฐธรรมนูญ` กลายเป็น `พ่ระราชบัญญัติ...`
2. `kind.py` เรียงยาวก่อนสั้นพร้อมคอมเมนต์อธิบาย แต่เลือกด้วย `min()` ที่เทียบสตริงต่อ
   `พระราชบัญญัติ` เลยชนะ `พระราชบัญญัติประกอบรัฐธรรมนูญ` ที่เริ่มตำแหน่งเดียวกัน
3. ตัวซ่อนการอ้างอิงกฎหมายอื่น ลบ**ชื่อเรื่องของเอกสารเองด้วย** เพราะรูปแบบเหมือนกันเป๊ะ

### รันซ้ำในนาทีเดียวกัน → ยืมคำตอบจากตัวเอง → ล้มทุกฉบับ

`--into` ใช้ timestamp ระดับนาที รันสองครั้งติดกันได้โฟลเดอร์เดียวกัน แล้ว `--skip-done`
ไปเจอคำตอบของรอบแรกในโฟลเดอร์ที่ตัวเองกำลังเขียน สั่งคัดลอกไฟล์ทับตัวเอง

```
100001.pdf ล้ม: SameFileError: .../identity.json and .../identity.json are the same file
0 แถว → result.csv
```

ล้มทุกฉบับแต่**ล้มเงียบ** เพราะ `except Exception` จับไว้ ได้ไฟล์ที่เปิดได้ อ่านได้ ไม่มีข้อมูล

### คำตอบที่ล้มเขียนทับคำตอบที่สำเร็จ

เจอตอนไล่ตัวข้างบน ถ้ารันซ้ำแล้วคีย์หมดอายุ คำตอบที่จ่ายเงินไปแล้วถูกทับด้วย
`{"ok": false}` และรอบถัดไปไม่มีทางรู้ว่าเคยมีของดีอยู่ — อันตรายกว่าตัวแรกมาก
เพราะตัวแรกเห็นทันทีว่า CSV ว่าง ส่วนตัวนี้เงียบสนิท

### ไม่มีคีย์ → เขียนไฟล์ 51 แถวที่มีแต่เลขเอกสาร

เดิมโปรแกรมเตือนทีละฉบับแล้วรันต่อ ได้ไฟล์ที่หน้าตาเหมือนผลลัพธ์ ตอนนี้หยุดทันที
พร้อมบอกวิธีตั้งค่า และหาคีย์จาก `.env` ด้วย ไม่ใช่แค่จาก environment

Core/Support · เหตุผล · สรุป · คำแนะนำ · ใบอนุญาต · แท็กสามชุด

### ทำไมชื่อคอลัมน์มีช่องว่างท้าย

`"ชื่อไฟล์ "` `"คำแนะนำสิ่งที่ต้องทำ "` `"ระดับวามเสี่ยง "` — สามอันนี้มีช่องว่างต่อท้าย
และอันที่สามสะกดตกตัว ค ทั้งหมดคัดมาจากไฟล์ผู้ดูแลตรงตัว **ไม่แก้** เพราะชื่อคอลัมน์ที่
เปลี่ยนเงียบๆ จะทำให้ทุกคอลัมน์หลังจากนั้นเลื่อนและอ่านเป็นผิดหมดตอนเทียบ

## ฐานข้อมูล

**ยังไม่ใช้ และยังไม่มี migration** ทุกอย่างเป็นไฟล์ — PDF เข้า CSV ออก หลักฐานอยู่ใน
โฟลเดอร์ที่เปิดอ่านได้ ไม่มีสถานะที่ต้องย้ายรุ่น ไม่มีอะไรพังเพราะ schema ไม่ตรง

จะได้ใช้เมื่อไหร่ก็ตอนที่ต้องการอย่างใดอย่างหนึ่งจริงๆ:

- คิวรีข้ามฉบับ — "กฎหมายทุกฉบับที่ผูกพันผู้ประกอบการอาหาร"
- คิวรีวิว หลายคนแก้ผลเดียวกัน ต้องรู้ว่าใครแก้อะไร
- ความสัมพันธ์กฎหมายแม่-ลูก ที่ต้องเดินตามโยงหลายชั้น

ถึงตอนนั้นค่อยเพิ่ม `alembic/` แล้วเขียน migration เป็นเรื่องๆ — สร้างไว้ก่อนโดยไม่มี
อะไรใช้ คือหนี้ที่ต้องดูแลโดยไม่ได้อะไรกลับมา

## เรื่องเงิน

พรอมป์ที่ยาวถูก cache ไว้ฝั่งผู้ให้บริการ ส่งครั้งเดียวใช้ได้ทั้งรอบ

`prompt_token_count` **นับ token ที่มาจาก cache รวมอยู่ด้วย** ถ้าดูแต่ตัวนี้จะแยกไม่ออก
ว่ารอบไหน cache ทำงาน — ผมเคยรายงานผิดมาแล้วว่า cache ใช้ได้ ทั้งที่ตัวเลขแทบไม่ขยับ
ตอนนี้บันทึก `cached` แยกไว้ ดูได้ใน `<คำถาม>.json`

```json
"cost": { "input": 3258, "cached": 1150, "output": 55, "billed_input": 2396, "ms": 5274 }
```

## ยังไม่ได้ทำ

- `ลิงค์PDF` — รอไฟล์ mapping จากผู้ดูแล เป็นคอลัมน์เดียวที่ได้ 40 ช่องกลับมาแบบไม่ต้องเดา
- `วันที่สิ้นผล` — ต้องรู้จากเอกสารฉบับอื่น
- `โทษเชื่อมโยงจากกฎหมายแม่` (7 ฉบับ) — ทดสอบ 3 สูตร ดีที่สุดได้ถูกเพิ่ม 5 เสีย 5 สุทธิศูนย์
  เพราะขึ้นกับว่ากฎหมายแม่มีโทษไหม ซึ่งไม่ได้เขียนในเอกสารลูก
- `100008` จังหวัด/อำเภอ — เขียนแค่ `ศาลแขวงเชียงดาว` ไม่บอกจังหวัดที่ไหนเลยทั้งฉบับ
  ต้องมีตารางอำเภอ→จังหวัด ซึ่งเป็นข้อมูลเขตปกครองจริง ไม่ควรเดาเอาเอง
- `data/audience-tree.txt` — พอร์ตมาแล้ว แต่ชื่อโหนดจับคู่กับไฟล์อ้างอิงได้ 0/40
  ต่อเข้าพรอมป์ตอนนี้จะทำให้แย่ลง ควรเป็นฟิลด์แยกต่างหาก
