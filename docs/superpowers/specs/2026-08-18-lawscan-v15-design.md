# lawscan-v15 — วาง txt ลง text/ สั่งคำสั่งเดียว ได้ CSV

โปรเจกต์แยก อยู่ข้าง ๆ `lawscan` ไม่ใช่ข้างใน อ่านไฟล์ข้อความทุกไฟล์ในโฟลเดอร์
`text/` ของตัวเอง ส่งให้โมเดลด้วย `prompts/v15.md` ครั้งเดียวต่อหนึ่งฉบับ
แล้วเขียน CSV รูปแบบเดียวกับที่ผู้ดูแลใช้

ไม่มีชั้นกฎ ไม่มีการรวมคำตอบ ไม่มีการตัดสินว่ากฎหรือโมเดลชนะ

```
~/Documents/lawscan/        ของเดิม ไม่ถูกแตะ
~/Documents/lawscan-v15/    อันนี้
```

---

## ทำไมถึงมีของชิ้นนี้

`lawscan` เดินสี่ขั้น — กฎรันก่อน ถามโมเดลห้าคำถาม รวมโดยกฎชนะ แล้วกฎรันอีกรอบ
ชั้นกฎคือ 2,927 บรรทัดใน 14 ไฟล์ และเป็นที่ที่ต้องแก้โค้ดทุกครั้งที่อยากเปลี่ยน
พฤติกรรม

`lawscan-v15` ตอบคำถามคนละข้อ: **ถ้าให้โมเดลตัดสินทุกช่องด้วยคำสั่งชุดเดียว
โดยไม่มีกฎช่วยเลย จะได้อะไร และแก้ที่ prompt ไฟล์เดียวได้จริงไหม**

อยู่คนละโฟลเดอร์เพราะสิ่งที่มันจะพิสูจน์คือ "ไม่ต้องมีของพวกนั้นก็ได้" — อยู่ในรีโป
เดียวกันแล้วเผลอ import อะไรสักอย่างมาใช้ คำถามก็ตอบไม่ได้อีกต่อไป

เทียบผลกันได้เพราะเขียน CSV รูปแบบเดียวกัน

## ตัวเลขที่วัดมาแล้ว

สิบฉบับ 100001–100010 · `gpt-5-nano` · เทียบกับ `data/expected.csv` · 210 ช่องที่นับ

| ทาง | ตรงเป๊ะ | รวมตรงบางส่วน |
|---|---|---|
| กฎ + ห้าคำถาม (lawscan วันนี้) | 56.9% | 64.9% |
| กฎ + V15 หนึ่ง prompt | 54.8% | 59.8% |
| กฎอย่างเดียว ไม่เรียกโมเดล | 51.9% | 55.0% |
| **V15 อย่างเดียว ตัดข้อความที่ 12,500** | **43.5%** | **47.1%** |
| V15 อย่างเดียว ส่งเต็มฉบับ | 40.3% | 44.1% |
| V15 อย่างเดียว ส่งเต็ม + ติดป้ายหัวกระดาษ | 42.9% | 46.7% |

สองบรรทัดที่มี "ส่งเต็ม" มาจาก spike ที่ทดสอบว่าการยื่นเอกสารทั้งฉบับและการยก
หัวกระดาษออกมาให้ จะทำให้โมเดลแทนกฎได้ไหม — **ช่วยไม่พอ** วันเดือนปีขยับจาก 5 เป็น 7
จาก 10 แต่ `กฎหมายแม่` ตกจาก 5 เหลือ 2 เพราะเอกสารเต็มฉบับมีชื่อกฎหมายอ้างถึง
เต็มไปหมด สุทธิแล้วแย่ลง

`วันทีมีผลใช้บังคับ` ติดที่ 3 จาก 10 ทุกแบบ เทียบกับกฎที่ได้ 10 จาก 10 เพราะช่องนี้
ต้องคำนวณ ไม่ใช่อ่าน — "เมื่อพ้นกำหนดหกสิบวันนับแต่วันประกาศ" คือวันประกาศบวกหกสิบ

เก็บไว้เองก่อน

## คำสั่ง

**ไม่ต้องมีอาร์กิวเมนต์** — `text/` คือที่ของมัน `out/` ก็เหมือนกัน

```bash
lawscan-v15                    สแกนทุกไฟล์ใน text/ ที่ยังไม่ได้สแกน → out/result.csv
lawscan-v15 --dry-run          ดูว่าจะสแกนกี่ฉบับ ไม่เรียกโมเดล ไม่เสียเงิน
lawscan-v15 --limit 3          เอาแค่สามฉบับแรกที่ยังไม่ได้สแกน
lawscan-v15 --batch 5          ทำพร้อมกันครั้งละห้าฉบับ
lawscan-v15 --fresh            ไม่สนของเก่า ถามใหม่ทุกฉบับ
lawscan-v15 --by-name-only     เช็คชื่อไฟล์อย่างเดียว ไม่ดูว่าเนื้อไฟล์เปลี่ยน
lawscan-v15 --chars 12500 --tail 2500    โหมดตัดข้อความ สำหรับวัดเทียบ
lawscan-v15 --text อื่น/ --out ที่อื่น/  ถ้าอยากชี้ไปที่อื่นจริง ๆ
```

ขั้นตอนใช้งานทั้งหมดคือสามอย่าง

```bash
cp ~/ที่ไหนสักแห่ง/*.txt text/     วาง
lawscan-v15                        สแกน
open out/result.csv                ดู
```

## กฎเหล็กข้อเดียว

**ห้าม `import lawscan`** — ตอนนี้เป็นจริงโดยอัตโนมัติเพราะอยู่คนละโฟลเดอร์ และมี
เทสต์บังคับไว้อีกชั้นเผื่อมีคนเติม path เข้ามาทีหลัง

ราคาของมันคือโค้ดที่ซ้ำกับ lawscan ราว 150 บรรทัด — การจัดระเบียบคำตอบ การเรนเดอร์
ทะเบียนหน่วยงาน รายชื่อคอลัมน์

**และไฟล์ข้อมูลที่คัดลอกมาสามไฟล์จะเดินห่างจากต้นฉบับเมื่อเวลาผ่านไป** —
`data/agencies.json` เป็นทะเบียนที่ผู้ดูแลแก้เรื่อย ๆ แก้ที่ lawscan แล้วที่นี่จะยังเป็น
ของเก่า นี่คือต้นทุนจริงของการแยกออกมา ไม่ใช่ข้อเสียสมมติ

ทางแก้ที่ไม่ทำ: symlink หรือ import ข้ามโปรเจกต์ — ทั้งคู่ทำให้ "แยกออกมา" ไม่จริง
ทางแก้ที่ทำ: `README.md` เขียนคำสั่ง `cp` สามบรรทัดไว้ให้ และ `lawscan-v15` พิมพ์
วันที่ของไฟล์ข้อมูลทุกครั้งที่รัน จะได้เห็นว่ามันเก่าแค่ไหน

## เส้นทางข้อมูล

```
text/100002.txt
  → intake      รวมไฟล์ ยุบซ้ำ ตรวจชื่อชน
  → ledger      สแกนไปแล้วหรือยัง (ชื่อไฟล์ + sha)
  → read        ข้อความ · เต็มฉบับ (ล้มค่อยถอย)
  → lists       prompts/v15.md + taxonomy + ทะเบียนหน่วยงาน
  → model       เรียกครั้งเดียว → JSON ตาม schema
  → tidy        จัดรูปคำตอบ
  → sheet       out/result.csv
```

ไม่มีขั้นตอนไหนตัดสินแทนโมเดล นอกจาก `tidy` ซึ่งจัดรูปคำตอบ ไม่เปลี่ยนคำตอบ

## บันไดถอย

```
ขั้น 1  เต็มฉบับ ไม่ตัด                              ← ค่าเริ่มต้น
ขั้น 2  ล้ม → หัว 10,000 + [ตัดกลาง] + ท้าย 2,500
ขั้น 3  ล้ม → หัว 4,000
ขั้น 4  ล้ม → เขียน error แถวยังออกโดยมีเลขเอกสาร
```

**นับว่าล้มเมื่อ** provider ตอบ error (รวม context length) · timeout 180 วินาที
หลัง retry สองครั้ง · คำตอบไม่ใช่ JSON หลัง retry · คำตอบเป็น object ว่าง

ทุกฉบับบันทึก `"attempt": "full" | "budget" | "small"` ลงไฟล์ JSON เพื่อให้นับได้ว่า
ขั้นไหนทำงานกี่ครั้ง โดยไม่ต้องเดา

เอกสาร 79% ของคลังสั้นกว่า 12,500 ตัวอักษรอยู่แล้ว ทั้งสามขั้นจึงส่งเท่ากัน บันได
มีผลจริงกับ 731 ฉบับที่เหลือ และเอกสารที่ยาวที่สุด 723,583 ตัวอักษร ≈ 249,511 token
ยังไม่ชน context 400k ของ gpt-5-nano — **บันไดจะทำงานเพราะ timeout เป็นหลัก
ไม่ใช่เพราะยาวเกิน**

## รู้ว่าไฟล์ไหนสแกนไปแล้ว

กุญแจคือ **ชื่อไฟล์ไม่รวมนามสกุล** — `text/100002.txt` จำคำตอบไว้ที่
`out/answers/100002.json` เจอไฟล์นั้นและข้างในเขียน `"ok": true` แปลว่าทำแล้ว ข้ามไป
ไม่เรียกโมเดล

ก่อนเรียกโมเดลฉบับแรก พิมพ์สรุปให้เห็นก่อนจ่ายเงิน

```
text/ มี 240 ไฟล์ · สแกนแล้ว 217 · ต้องสแกน 23 · ข้อความเปลี่ยน 2
prompts/v15.md 18 ส.ค. · data/agencies.json 10 ส.ค.
```

**ข้อความเปลี่ยนหลังสแกนไปแล้ว** — เก็บ `"source_sha"` แปดตัวแรกของ sha256 ของไฟล์ txt
ไว้ด้วย ชื่อตรงแต่ sha ไม่ตรง แปลว่าไฟล์ถูก OCR ใหม่ → สแกนใหม่ พร้อมบอกใน log ว่า
เพราะข้อความเปลี่ยน ไม่ใช่เพราะลืม ปิดด้วย `--by-name-only`

เหตุผลที่ตั้งเป็นค่าเริ่มต้น: การ OCR ซ้ำแล้วได้ข้อความดีขึ้นเกิดจริงในโครงการนี้
(lawscan มีโฟลเดอร์ `text-prev` เป็นหลักฐาน) และคำตอบเก่าที่ค้างอยู่เงียบ ๆ บนข้อความ
ที่ถูกแทนที่ไปแล้วคือความผิดพลาดที่มองไม่เห็นจนกว่าจะสาย

**ชื่อไฟล์ซ้ำ** เกิดไม่ได้แล้วเพราะอ่านโฟลเดอร์เดียว แต่ `--text` ชี้ไปที่อื่นได้
จึงยังตรวจไว้ เจอแล้วหยุดพร้อมบอกว่าคู่ไหนชน

## CSV ที่ออกมา

**มีทุกไฟล์ใน `text/`** ไม่ใช่เฉพาะฉบับที่เพิ่งสแกน — ฉบับที่ข้ามประกอบแถวจากคำตอบ
ที่บันทึกไว้ ไม่งั้น CSV จะหดลงทุกครั้งที่รันซ้ำ ซึ่งเป็นกับดักที่ตรงข้ามกับจุดประสงค์
ทั้งหมดของการวางไฟล์เพิ่มทีละนิด

จำนวนแถว = จำนวนไฟล์ใน `text/` เสมอ แม้ฉบับนั้นจะล้ม

## ชิ้นส่วน

### intake.py
`gather(folder) -> list[Path]` ทุก `*.txt` ชั้นเดียว เรียงตามชื่อ ยุบซ้ำด้วย
`Path.resolve()`

`collisions(files) -> dict[str, list[Path]]` ชื่อไม่รวมนามสกุลที่ซ้ำกัน คืนให้ cli
หยุดและรายงาน

### ledger.py
`done(answers, path, by_name_only=False) -> bool` มี `<ชื่อ>.json` ที่ `ok: true`
และ `source_sha` ตรงหรือไม่

`sha(path) -> str` แปดตัวแรกของ sha256 · `load(answers, name) -> dict | None`
คำตอบที่บันทึกไว้ สำหรับประกอบแถวของฉบับที่ข้าม

`save(answers, name, answer)` — **คำตอบที่ล้มไม่ทับคำตอบที่เคยสำเร็จ**

### read.py
`load(path) -> str` อ่าน utf-8

`fit(text, head, tail) -> str` `head=0` คืนทั้งหมด มิฉะนั้นตัดหัว ต่อป้าย
`[…ตัดเนื้อหาส่วนกลางออก…]` แล้วต่อท้าย เอกสารสั้นกว่างบไม่ถูกแตะ

ไม่ทำสิ่งที่ `lawscan.ocr.budget.fit` ทำเพิ่ม — ไม่กู้ย่อหน้า "หมายเหตุ :- เหตุผล
ในการประกาศใช้" ไม่กู้ประโยคที่มีชื่อใบอนุญาตจากกลางเอกสาร **ข้อนี้มีราคาที่ยังไม่ได้
วัด** และมีผลเฉพาะเอกสารที่ยาวเกินงบ (2 จาก 10 ฉบับในชุดทดสอบ) ถ้าโหมดตัดออกมาแย่กว่า
คาดมาก ที่นี่คือที่แรกที่ต้องดู

### answer.py
schema 33 ฟิลด์ ตรงกับที่ `prompts/v15.md` สั่ง และแผนที่ฟิลด์ → ชื่อคอลัมน์ ตัวอักษร
เดียวกับที่ผู้ดูแลใช้ ประกาศไว้ที่นี่ที่เดียว

### model.py
คุยกับ provider ที่พูด OpenAI chat API (`gpt-5-nano` ค่าเริ่มต้น) ส่ง `response_format`
แบบ `json_schema` `strict: true` คำสั่งนำหน้าเสมอเพื่อให้ prefix cache ทำงาน —
prompt คือ 35k token และเป็นส่วนใหญ่ของบิล

คีย์อ่านจาก env `OPENAI_API_KEY` ก่อน แล้วจึงจาก `.env` ไม่ log ไม่พิมพ์
Gemini ยังไม่รองรับ เพิ่มทีหลังเป็นไฟล์เดียว

### tidy.py
สิ่งที่ตัดออกไม่ได้ถ้าอยากได้ 43.5% เพราะตัวเลขนั้นวัดตอนมีชั้นนี้ครบ

| ทำอะไร | ทำไมตัดไม่ได้ |
|---|---|
| ทุกวิธีเขียนคำว่าไม่มี (`null` `""` `ไม่มี` `None` `nan`) เหลือค่าเดียว | V15 ตอบ `core: ["-"]` และ `note: "-"` เป็นปกติ |
| รายการ join ด้วยคอมม่า ทิ้งสมาชิกที่แปลว่าไม่มี | `["ใบอนุญาต ก", null]` คือหนึ่งใบ ไม่ใช่หนึ่งใบกับรู |
| ยุบซ้ำใน 6 ฟิลด์รายการ | prompt สั่งให้ตอบชื่อกว้างคู่ชื่อเฉพาะ ตรง ๆ แล้วได้ชื่อกว้างซ้ำสามครั้ง |
| `parents` เป็นบรรทัด `ชื่อกฎหมาย มาตรา X` | รูปแบบที่ไฟล์อ้างอิงเขียน |
| ทิ้งรัฐธรรมนูญออกจาก `parents` | อำนาจออกกฎหมายเป็นของทุกฉบับ ไม่บอกว่าฉบับนี้ออกตามอะไร |
| `agencies` สะกดตามทะเบียน ตามด้วยกระทรวง | เป็นการค้นตาราง ไม่ใช่การตัดสิน — และเป็นคอลัมน์ที่ V15 ทำได้ดีที่สุด |
| `audience` จัดรูปรายการ | สองกลุ่มที่ต่อด้วย "และ" อ่านเป็นกลุ่มเดียว |
| แปดคอลัมน์ที่ความว่างคือคำตอบ เขียน `-` | ไฟล์อ้างอิงเขียนแบบนั้น ช่องว่างจะอ่านเป็นคำถามที่ไม่มีใครไปถึง |

## เทสต์

ไม่แตะเน็ต ไม่แตะโมเดล ทุกข้อคุมพฤติกรรมที่เสียคะแนนได้จริง

- `import lawscan` ไม่ปรากฏใน `src/v15/` แม้แต่ที่เดียว
- `tidy` ทิ้ง `-` ออกจากรายการ และ `["-"]` กลายเป็นช่องว่าง
- `tidy` ยุบรายการซ้ำ
- `parents` จัดรูปถูก และรัฐธรรมนูญถูกทิ้ง
- `section` ที่เป็น `null` ไม่กลายเป็นคำว่า `None`
- แปดคอลัมน์ที่ความว่างคือคำตอบได้ `-` คอลัมน์อื่นได้ช่องว่าง
- `ลำดับ` มาจากเลขเอกสาร ไม่ใช่ตำแหน่งในรอบรัน
- CSV เรียงคอลัมน์ถูกทั้ง 36 และมี BOM
- `fit` ตัดตรงตำแหน่ง และไม่แตะเอกสารที่สั้นกว่างบ
- บันไดถอยลงขั้นเมื่อล้ม และบันทึก `attempt` ถูก
- คำตอบที่ล้มไม่ทับคำตอบที่สำเร็จบนดิสก์
- ฉบับที่มีคำตอบ `ok: true` แล้วถูกข้าม ไม่เรียกโมเดล
- ฉบับที่ `source_sha` ไม่ตรง ถูกสแกนใหม่ · `--by-name-only` ทำให้มองข้าม
- CSV มีแถวครบทุกไฟล์ใน `text/` รวมฉบับที่ข้ามและฉบับที่ล้ม
- `--dry-run` ไม่เรียกโมเดล · `text/` ว่างแล้วไม่ crash
- prompt ไม่มี `{{...}}` หลงเหลือหลังเติม list

## เกณฑ์ยอมรับ

**ด่านที่ 1 — ชั้น `tidy` ต้องซื่อตรง (ตัดสินได้ ไม่ขึ้นกับโมเดล)**

คัดลอกของทดสอบเข้ามาเก็บใน `tests/fixtures/` ตอนตั้งโปรเจกต์

```
lawscan/out/exp-v15/documents/*/v15.json   คำตอบดิบสิบฉบับ
lawscan/out/exp-v15-model-only.csv         ผลที่ผ่านชั้นจัดระเบียบของ lawscan
```

ป้อนคำตอบดิบสิบไฟล์นั้นเข้า `v15.tidy` กับ `v15.sheet` ผลลัพธ์ **ต้องตรงกับ
`exp-v15-model-only.csv` ทุกตัวอักษร**

ไฟล์นั้นคือคำตอบชุดเดียวกันที่ผ่านชั้นจัดระเบียบของ lawscan และให้คะแนน 43.5%
ตรงเป๊ะ ด่านนี้จึงพิสูจน์ว่าโค้ดที่เขียนใหม่ทำงานเท่าของเดิม โดยไม่ต้องจ่ายค่าโมเดล
และไม่ขึ้นกับความไม่แน่นอนของโมเดล เป็นเทสต์ในชุด ไม่ใช่การรันมือ

**ด่านที่ 2 — รันจริง (รายงาน ไม่ใช่ประตูผ่าน)**

```bash
cp ~/Documents/lawscan/text/10000{1,2,3,4,5,6,7,8,9}.txt ~/Documents/lawscan/text/100010.txt text/
lawscan-v15 --chars 12500 --tail 2500
cd ~/Documents/lawscan && ./.venv/bin/lawscan diff ~/Documents/lawscan-v15/out/result.csv
```

คาดว่าราว 43.5% แต่ **ไม่ตั้งเป็นเกณฑ์ผ่าน** เพราะโมเดลตอบไม่เหมือนเดิมทุกครั้ง และ
เพราะ `fit` ที่ง่ายกว่าจะทำให้สองฉบับยาวได้ข้อความไม่เหมือนตอนวัด

จากนั้นรันด้วยค่าเริ่มต้น (เต็มฉบับ) เพื่อดูตัวเลขของโหมดที่จะใช้จริง — spike วัดไว้
ที่ 40.3%

การให้คะแนนใช้ `lawscan diff` ของโปรเจกต์เดิม ซึ่งไม่ใช่การพึ่งพาในโค้ด แต่เป็น
เครื่องมือคนละตัวที่อ่าน CSV รูปแบบเดียวกัน

## สิ่งที่ยังไม่รู้

`lawscan-v15` จะได้ราว 43.5% ซึ่งต่ำกว่า lawscan วันนี้ 13.4 จุด สิ่งที่ยังไม่รู้คือ
